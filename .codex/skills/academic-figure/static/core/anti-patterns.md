# 图表反模式（Figure Anti-Patterns）

| 模式 | 问题 | 正确做法 |
|---|---|---|
| 美观优先 | 使用 rainbow/jet 色板让图“好看” | 使用灰度安全、克制的学术色板 |
| 无 QA 交付 | 代码跑通就直接交付 | 必须执行 QA Contract：可读性、数据一致性、格式合规 |
| 虚构架构 | 人工绘制需求记录中包含不存在的模块连接 | 架构信息只能来自代码/论文证据；未确认项必须标记 |
| 架构图越界 | 用 Python boxes/arrows、SVG 或生图 prompt 勉强绘制模型框架图 | 标记为人工绘制需求，只给证据清单、caption 草案或 blueprint notes |
| 硬编码路径 | 文件路径写死为开发者本地路径 | 使用相对路径或参数化配置 |
| 只交付 prompt | 用户要求数据图时只给外部提示词 | 数据图必须交付脚本、源数据路径、SVG 和 QA 报告 |
