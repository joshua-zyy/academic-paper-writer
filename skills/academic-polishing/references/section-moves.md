# 章节论证功能参考

推荐顺序按请求和材料调整，不是实验、段落、引用或篇幅配额；官方要求优先。主旨是每段有作用，新增解释同时删除重复。

| 章节 | 论证功能与可用句式 |
|---|---|
| Introduction | 具体任务→相关已有路线→明确问题→本文桥接。`We address ... in ...`；已有关键结果可简述，不编缺口 |
| Related Work | 按相关比较维度综合→最近邻工作差异。`A line of work ...`、`A key distinction is ...`，不要纸名排队 |
| Method | 符号/输入输出→数据流→核心操作及作者意图→训练/推理。`Let ... denote ...`、`During inference, ...` |
| Experimental Setup | 已有数据/划分、预处理、训练选择、指标、比较条件，未知不填。`We evaluate ... on ...` |
| Results | 问题→决定性数值/图表→关键模式；可选分析只写实际已做。`Table X reports ...` |
| Discussion | 综合发现→与文献合理解释→集中适度局限→具体下一步；不重复 Results 或逐句防御 |
| Conclusion | 问题/方法→已支持主要发现→简洁意义；无新数据、空泛愿景或重复局限清单 |
| Abstract | 主体确定后凝练问题/方法/已有结果；材料不足给框架，不声称完整实证 |
| Title | 可检索、具体、准确，不靠 novel/powerful 或大量缩写 |

上述句式只在内容真实时使用。不得用“Extensive experiments”“first”“fair comparison”等模板补未确认事实。不把常见 CS 会议习惯写成所有 venue 的官方规范。
