# Method 叙事

将代码讲解、公式清单或提纲改成读者能理解的系统描述：任务与符号 → 整体数据流 → 核心机制与作者设计意图 → 训练/推理。按实际方法组织，不逐模块强制六步。

核心模块讲作用、输入输出、运算和必要理由；标准组件简写。公式需要时给，并解释符号和与机制的关系，不能仅为显专业造伪公式。

设计意图来自作者或设计材料。代码确认运算但不能独自证明“为解决某瓶颈而设计”；缺意图列 RATIONALE_NEEDED，不把推断改成确定作者目的。

段落自然解释“什么、怎么、为什么”，不写“代码中调用 forward”“合理性在于”等内部讲解。无需每模块末尾附局限句；真正必要的边界在 Discussion 集中处理。

独立修改允许重排已给内容；新事实/核心主张需要作者确认。交付文本与必要缺项，不无限改写或强制扩写。
