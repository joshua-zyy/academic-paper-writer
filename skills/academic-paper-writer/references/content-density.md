# 最短充分论证检查

不是段落、字数、公式或 work-cluster 配额。判断读者能否理解本节要完成的论证，以及当前材料能支持到哪里。

| 章节 | 功能缺口 |
|---|---|
| introduction | 问题、已有工作与本文主线之间没有衔接 |
| related_work | 只有论文名单，没有相关比较维度与本文定位 |
| method | 操作、数据流、符号或作者设计意图无法理解 |
| experimental_setup | 实际协议/指标缺项或描述不清 |
| results | 没有回答结果问题，只逐项复述数值 |
| discussion/conclusion | 解释与已有发现脱节，或只有空泛愿景 |

有材料时补理解链、重排或压缩，不仅扩写。无材料时保留框架与具体补充建议，不制造长篇空话。

每次新增解释先问其功能是否已在别处出现；优先替换、合并、删除重复，必要支持细节可放图注、Methods 或作者后续补充材料。不能把改变主结论的矛盾藏起来。
